Dynamic Soundtracker

This is a browser-based audio instrument for extended sessions of focused work such as study or activity completion. The way it works is that a person sets a session, steps away and returns to a branch-like structure that has grown while they were gone. A series of tiles will appear, having grown off of the trunk, which can be hovered over to play a musical note and display varying colour.

My Assignment 1 concept was leaning heavily into passive user engagement, these prototypes aim to continue the core idea of a growing branch/tree like structure but explore how the experience can become more interactive. The two areas approached in assignment 2 are Layout, which depicts how the tree is structured and aligned to the screen and the extended technique of Randomness, which displays how Math.random() shapes what each tile looks like, sounds like and when it appears.

All of the 6 prototypes use Tone.js for sound, allowing users to trigger feedback from the dynamic soundtracker by hovering over a tile or moving keyboard focus onto it, making it play a distinct note. The branch structures are drawn on an HTML canvas, with each prototype being a separate branch of one repository, published through GitHub Pages.

Area 1 - Layout Prototypes

The Layout area explores how the structure of the branches changes the position in which tiles are read and approached. To create that, every layout prototype uses the same neutral grey circular tiles, the same blue hover and the same random note, so the arrangement is the only thing that changes.

Prototype 1: Central Trunk

This first layout prototype depicts a single vertical trunk with branches alternating left and right. This is the most familiar reading of a tree and acts as the reference structure for the other two following layout prototypes. Its symmetry keeps every circular tile visible and within close reach for users, this works well as an instrument that is hovered over to produce sound rather than clicked. Additionally the bottom-to-top order can be read as time passing and can feel quite neat and ordered.

Prototype 2 - Off Centre Diagonal Growth

This second layout prototype sees the tree trunk run diagonally from the lower left to upper right, it remains centred in the space just below the heading, with branches of uneven length on either side. Removing the vertical axis makes the structure asymmetric and more organic, closer to the irregular branching reference image sourced from Pinterest. This experiment tests a less formal structure for a tool that is meant to sit quietly in the background, which I think could support a more organic and interactive user experience.

Prototype 3 - Abstract Point Growth

This final layout exploration is an abstract approach that features one tree root that splits into three anchor points, and each anchor grows its own cluster of tiles. It clusters group sounds together, exploring whether regions of the tree could stand for separate tasks or work sessions within one tree, and potentially could therefore give the user designated areas to move between while hovering.

Area 2 - Randomness Prototypes (extended technique)

The Randomness area explores how Math.random() can make every tree and every session different. The structure is fixed as the central trunk from layout prototype 1 so that only the random behaviour changes. The tile colours are drawn from a palette taken from the dusk-sky panels in the reference image.

Prototype 4 - Random Colour and Shape

In my first randomness prototype, Math.random() chooses each tile's note, a jagged outline, its size and a two-colour gradient. The shards respond to the stained glass tiles in the reference image and make every tile visibly distinct, so moving across the tree reads as moving between different pieces rather than repeating the hover over the same button.

Prototype 5 - Weighted Randomness

The second randomness prototype I made matches the first one, but instead of even odds, Math.random() is weighted so some notes and colours appear more often than others. C4 and deep blue are common, while A4 and amber are rare. Uneven odds give the tree a tonal centre and a dominant colour, and make the rarer tiles stand out as something to find when returning to the session. I think this could be good at building anticipation and encouraging the user to come back and review what has been created over their session.

Prototype 6 - Random Timing

My final randomness exploration was using Math.random() to determine the timing of when the branches and tiles appear one at a time after a random delay once the session begins, each with a soft chime as it arrives. This ties the randomness to the timer idea, since the tree grows while the user is away, and makes the order of growth unpredictable. Delays are set to about 15 seconds so the prototype can be tested quickly, a real session would spread them across minutes or hours.
